Campaign

Housekeeping over the whole case pool. Every action here reports before it changes anything.

Sites that are not on land

New cases are refused at POST /v1/cases if the building atlas publishes no tile for them. Cases drawn before that gate existed are still in the pool — the sampler's LCZ raster reads snow, ice and open water as built classes, so the draw placed sites in Antarctica and in the open ocean. Each one is 66 core-hours aimed at an empty flat plane.

Cases a broken node quarantined

Quarantine is meant to say "this site is broken everywhere". A node that could not run anything — a stopped container daemon, no solver installed — used to charge an attempt per lease instead, and three of those park a site with nothing wrong with it. Reopening puts them back in the pool with their attempts reset. Match on what the case last failed with, so this undoes one broken machine rather than releasing every genuinely degenerate site.

Move cases to another recipe

For a site its recipe cannot build. Each one is added again under the new recipe as a new case, which only nodes that know that recipe are given, and the old case is parked with a pointer to it. A case a node is working on is left alone — pull it off first.
Sign in as an operator or an admin to run campaign housekeeping.

Machines

One credential per worker. Revoking one leaves the rest running.

Node builds

Publish a build to the nodes' release share, register it here, move ONE worker to it, watch a few cases, then set it as the fleet's target. Nodes switch by themselves at the boundary you choose; a case is never touched by two builds without the archive saying so.
